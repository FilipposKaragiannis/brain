bump: minor

- Every adapter has `set-status` and `assign` (gh#177). `set-status <id> <status>` takes
  `backlog`, `ready`, `in-progress`, `needs-you` or `in-review`. `assign <id> me|none` adds or
  takes off the current user. Both are idempotent and print `<id> <value>` only on a change.
- The flow assigns and moves the card itself. A take assigns `me` when nobody holds the item,
  then sets in-progress. A raised gate sets needs-you, or in-review for the merge gate. A cleared
  gate sets in-progress again. The last step done sets in-review. A failed push warns, logs a
  `push failed` event and never fails the step; a landed push is kept in the record's `pushed`.
- New config keys. `github.claim_label` (opt-in) names a label that marks an issue in progress
  when there is no `github.project`. `jira.transitions.<name>` names the Jira transition
  `set-status` takes for each status.
- `sync` is gone, with `github/sync.sh` and the per-schedule loop in `jobs/next.sh`. A label
  write no longer moves a card, so a card moves once per change. Unstarted cards are no longer
  sorted between Backlog and Ready.
- `answers` takes the gated ids, which `jobs/next.sh` reads from the records. A gate the tracker
  does not show is still answered.
