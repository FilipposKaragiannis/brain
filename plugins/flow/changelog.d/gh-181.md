bump: minor

- Readiness now obeys the tracker's status category and assignees (gh#181). Every adapter item
  carries `category` (`todo`, `in-progress`, `review`, `blocked`, `done` or `unknown`, from the
  GitHub card's Status through `github.status.*`, the Jira status category or a status named in
  `jira.status.review` or `jira.status.blocked`, and the local item file's `workflow`) and
  `assignees` (a list). The mapping is in `adapters/README.md`, Category and assignees.
- Two new config keys: `ready.categories` (`todo`, `unknown`; default `[todo, unknown]`) and
  `ready.assignee` (`none`, `me`, `any`, a login or an email; default `[none, me]`). An item the
  flow does not hold yet is ready only when its category and its assignees match. The default
  hides items assigned to someone else, or to you and someone else; `ready.assignee: any` restores
  the old behaviour. A key written empty, an unknown category or an assignee with a space or a
  comma exits 2, naming the key.
- An item the flow holds (a claim in its record, or a tracker step with no record yet) is judged
  by neither, since the flow set its card and assignees. A claim made on another machine through
  a shared `state.dir` is never ready here.
- Each adapter has a new `me` operation (`me.sh`): the `gh` login, the Jira account id and
  `jira.email`, or the local git `user.email` and `user.name`. It runs only for an unheld item
  with an assignee the policy does not name while it names `me`, once per adapter per run, so
  `next.sh` may run it under the pick lock. A failed `me.sh` (offline, no token) stands for no one
  and says so once on stderr.
- `pick.<name>.assignee` takes a list: an item matches when any of its assignees is any of the
  names. A tracker scope's `assignee` still names one person. The console does not yet read a
  list `pick.<name>.assignee`; it shows the value raw.
- `next.sh` checks the policy again on the item it reads. Exit 4 now also covers a named item
  assigned to someone else, one in progress, in review or blocked on its tracker, and one held
  on another machine; a pick passes over such an item to the next. When nothing is ready, its
  last line counts them too.
- A GitHub card with no Status set reads `unknown`, like an issue with no card, so it stays ready.
  A card in a column outside `github.status.*` reads `blocked` and hides the item: on a board
  whose columns are not named `Backlog`, `Ready`, `In progress`, `In review` and `Needs you`, set
  `github.status.backlog`, `.ready`, `.running`, `.review` and `.gate` to its names.
- After `sync.sh` moves an epic's card to In progress, the epic reads `in-progress` until the
  next sync.
