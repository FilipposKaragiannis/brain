bump: major

- `tracker_state` now defaults to `none` (gh#182, ADR 0005): no flow label, state comment, Jira
  property, local frontmatter key or size reaches a tracker. `tracker_state: labels` keeps the
  old mirror for one release, for a machine that still runs an older flow. The key now switches
  the mirror only: an item with no flow record reads the tracker's state, and lists its run and
  gate files, in both modes, and its first write copies that state, but `size`, into a record.
  So work in flight carries over with no command.
- New `state.sh import [--dry-run] [--strip]`: every open item the trackers list that carries
  flow state and has no record gets one, through the same seed. An item whose worktree no
  `claim.json` on this machine names is skipped and said. An item it now holds is assigned and
  its status pushed. `--strip` then takes the `step:`, `gate:`, `wt:` and `flow:` labels and the
  state comment, property or frontmatter keys off the items recorded on this machine, through a
  temporary `strip-state` adapter op, and keeps the size. `--dry-run` says what it would do and
  changes nothing; `--strip` under `tracker_state: labels` exits 2.
- `next.sh` writes no size at a start: the size is the flow's own estimate, else the tracker's,
  so a size edited on the tracker is read until the flow re-sizes. A re-size writes
  `size_estimate` and posts one plain comment, "Re-sized S -> M at step implement.", with the
  profile change when the new size selects another.
- The profile is pinned at the first start. `next.sh <item> --profile <name>` and
  `flow:plan <item> --profile <name>` pin another; a name that is no profile, a started item
  whose step that profile lacks, and `--profile` with no item exit 2 and write nothing. The
  `flow:<profile>` label is no longer read.
- `link-pr` writes no state. Only orchestrator scripts call it, and they record `pr` and
  `pr_host` (the host the run started on); the pr-creator reports its PR in its result's `pr`.
- The health job says once how many open items still carry flow labels, and names
  `state.sh import --strip`; it says nothing under `tracker_state: labels`.
- Labels left at the upgrade are frozen: they are read for an item with no record on this
  machine (another machine advanced it, or a closed item came back after its record was
  archived) until a record exists. The health line and `import --strip` remove them. An item
  whose `wt:` label no machine backs is never imported or stripped; each run says so.
- A team upgrades in this order: keep `tracker_state: labels` until every machine runs this
  release, then run `state.sh import` on each machine, then drop the key, so `none` holds, and run
  `state.sh import --strip` on each. Two machines can otherwise both seed a started item that has
  no worktree.
