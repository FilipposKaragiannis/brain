bump: minor

- Init now migrates an existing `.flow/config.yaml` before it copies anything: it runs the plugin's
  ordered step list (`skills/init/migrations.json`), which looks only at the file, so a second run
  changes nothing. Comments, layout and line endings stay. The first step removes `retro.commit`,
  which nothing reads, and init's note about it is gone.
- The config now carries `config_version`, the flow version that last migrated it. A config
  without one gets it on the next init, so every existing project sees one migration with that
  line alone.
- Before it writes, init saves the config to `.flow/migrations/config.yaml.<version found>.bak`
  and appends the changes to `.flow/migrations/report.txt`, one line each: old key, new key,
  value and reason, split by tabs. An existing config records no version, so its first backup is
  `config.yaml.unversioned.bak`. A name already taken gets `.2`, `.3`.
- The first session start after a migrating init, in the main worktree or a pool worktree, prints
  its changes once, under a note for the owner. `report.txt` keeps the record.
- `init --check` lists each pending change as drift and writes nothing. A config outside the flat
  subset (tab or odd indentation, a key twice) is left as it is, with a note naming the line.
- Init moves `github.ready_needs` to `ready.needs` and `github.priority_order` to
  `ready.priority_order`, block lists and trailing comments too, into an existing `ready:` map
  after its comments, and removes a `github:` left empty. A `ready` key already set, even to an
  empty list, wins: the old key goes and the report says so. The flow still reads the old keys for
  one more release.
- Init spreads `jobs.model` and `jobs.effort` into `jobs.claude` and `jobs.codex`, each host
  reading what it read before: a host whose map is there already, even empty, gets nothing, and
  Codex gets the roster model under its Codex name. The old keys go, with a report line per host
  written. Codex takes no `max` effort, so a `jobs.effort: max` becomes an init gap naming
  `jobs.codex.effort`; Codex refused that effort before too. Init's note that the old keys are
  deprecated is gone. The flow still reads them for one more release.
